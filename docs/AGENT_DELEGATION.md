## 使用

1. 在“API 与模型”保存并启用主 Agent Provider。
2. 打开“子 Agent → 配置委派与预算”，启用子 Agent，选择“主 Agent 自主委派”。
3. 子 Agent 可继承主 Provider，也可选择另一个已保存的 Provider；模型可从已获取的模型列表选择或手填，留空继承所选 Provider。
4. 在 Copilot 选择 API 模型并发送分析目标。主任务异步创建，分析页展示进展、子任务树、模型、预算和停止入口。
5. 完成后，汇总回到 Copilot，同时写入待复核证据；每个子任务的结果也可单独查看。

旧配置默认迁移为手动模式。关闭子 Agent 后，Copilot 保持原有单次文本响应。保存设置只影响新任务，已启动任务使用创建时的配置。

## 预算语义

- `enabled`：是否允许创建子 Agent。
- `delegation_mode`：`manual` 或 `auto`。
- `provider_id`：子 Agent Provider，空字符串继承默认 Provider。选择已保存 Provider 表示允许本次委派使用该服务，不改变全局默认 Provider。
- `model`：子 Agent 模型覆盖，空字符串继承所选 Provider 的模型。
- `max_children`：单个主任务累计可创建的子 Agent 数，1–100。
- `max_concurrency`：单个主任务的子任务并发，1–8；所有主任务共用最多 8 个线程，同时最多 4 个主任务。
- `call_budget`：1–100。自动模式包括主 Agent 决策、无效响应重试、子任务和最终汇总。子任务派发前预占预算，界面显示已占用值；取消前已预占但未执行的调用不会退回。
- `time_budget_seconds`：主任务总执行时间预算，1–3600 秒；排队也消耗时间。

取消或超时后不再写入迟到结果。远程已发出的 HTTP 请求可能仍在服务方完成；这不代表远端计费被撤销。已完成子任务的证据会保留。

## 实现边界

`agent_orchestrator.py` 将主 Agent 决策循环从 `runtime.py` 分离，通过校验后的 JSON 文本动作 `spawn_agents` / `finish` 调度现有子任务执行器，因此不依赖服务端原生工具调用。

当前支持按批次并行委派，多批次分析和最终汇总。子 Agent 仅处理创建时提供的元数据、证据与 Skill 文本；不能递归创建 Agent、调用 MCP 或执行样本。主 Agent 等待当前批次结束后继续决策。持久化任务与证据，服务重启时将未完成任务标记失败，不自动重发请求。

APK 静态分析仍由独立 worker 执行；它不使用此委派调度器。网页新增 APK 分析目标，模型默认继承配置；通用目标不再绑定 Flare-On 格式。CLI 可通过 `--task` 指定目标与答案约定。

## 界面

- Agent 配置与运行记录分离，分析页按主任务展示可展开的子任务树。
- 自动刷新保留子任务树展开状态，任务计数以主任务为单位。
- 导航栏和 Copilot 可折叠；桌面端可拖动 Copilot 左边缘调整宽度，也可聚焦分隔线后使用左右方向键。
- 布局保存在浏览器本地；窄屏 Copilot 使用抽屉，Escape 可关闭。
- 失败、取消和完成任务的结束列使用明确文案；详细状态保留在任务卡片中。

## 验证

自动化测试覆盖自动委派与汇总、子模型和 Provider 覆盖、数量与调用预算、并发、取消后不写回、超时以及旧配置兼容；浏览器验收使用临时 Case 和本地模拟 Provider，不调用真实付费 API。
