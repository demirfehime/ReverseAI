# 后续架构与界面改造待办

更新日期：2026-09-23。

本文记录 Agent 自主委派改造后尚未完成的工作，供后续开发接续。以下未勾选项均为计划，不代表已实现；本次仅保存待办，不启动这些改造。

## 已完成的基础

- 主 Agent 通过 `spawn_agents` / `finish` JSON 动作按批次委派、回收结果并汇总。
- 配置子 Agent 开关、手动/自动模式、Provider、模型、累计数量、单任务并发以及调用和时间预算。
- 分析页展示父子任务、模型、预算、取消入口和证据；配置页与运行记录分离。
- 导航与 Copilot 可折叠，Copilot 宽度可调整并记忆。
- APK 支持自定义分析目标，默认模型继承配置，不再写死 Flare-On 目标。

使用方式及准确的预算语义见 [Agent 自主委派说明](AGENT_DELEGATION.md)。

## 1. 统一 Agent 与 APK 调度（优先级 P1）

现状：`agent_orchestrator.py` 负责文本委派；`runtime.py` 保留单次 Copilot 与手动子任务；`apk_jobs.py` 管理独立进程，`apk_analysis.py` 有独立决策循环。APK 不参与自主委派的统一预算与调度。

- [ ] 提取统一的任务、运行状态、预算、取消和事件接口，允许挂接文本执行器与 APK worker。
- [ ] 将 APK 读取、检索、资源和受限计算能力注册为明确的工具接口，供主 Agent 按任务选择；保留 APK 独立进程边界。
- [ ] 主任务与子任务共享可追溯的证据引用、模型调用记录和预算账本，避免各执行器分别计费导致超限。
- [ ] 统一任务失败、取消、超时与服务关闭行为，防止取消后的迟到结果写回。
- [ ] 明确配置迁移策略，并保留现有 API、网页与 CLI 的兼容入口。

验收：同一分析目标可完成“读取 APK 证据 → 委派独立分析 → 回收证据 → 主 Agent 汇总”；总调用与并发不超限，取消覆盖整个任务树；原有手动、单次 Copilot 和 APK 测试继续通过。

## 2. 持续子 Agent 上下文与协作（优先级 P2，依赖统一调度）

现状：每个子任务只进行一次模型调用，输入为创建时的证据快照；主 Agent 等待当前批次全部完成后继续。尚无对子 Agent 的追加任务、消息交互或独立工具循环。

- [ ] 增加持久化的子 Agent 会话上下文，支持向已有子 Agent 追加任务。
- [ ] 根据实际需要提供列表、等待、消息和单子任务取消接口，并校验任务归属。
- [ ] 支持部分子任务完成后通知主 Agent，不要求每次等待整个批次。
- [ ] 定义历史压缩与证据选取规则，避免上下文无限增长或丢失关键引用。
- [ ] 将全局并发和同时运行主任务的上限配置化；当前分别固定为 8 个子任务线程与 4 个主任务。

验收：追加任务能引用该子 Agent 的既有结果，跨 Case 不串上下文；重试、追加调用都计入预算；单子任务失败不丢失其他已完成结果。

递归创建子 Agent 和自动执行样本不属于默认目标。若后续扩展，需另行定义深度、数量与执行权限，不能因统一调度而默认开启。

## 3. SQLite 存储迁移（优先级 P1，可独立设计）

现状：`server.py` 中的 `Store` 通过锁和原子替换读写整个 `data/state.json`。高频任务事件会增加整文件读写开销。

- [ ] 提取 Repository 接口，分离 API 业务逻辑与持久化实现。
- [ ] 设计 Case、样本、任务、消息、证据、报告、配置和事件的数据表及索引。
- [ ] 用事务实现任务状态、预算与证据写入的一致性，保留审计链和报告冻结快照语义。
- [ ] 编写可重复运行的 JSON 导入工具，迁移前备份，校验记录数、关联关系、审计链和报告哈希。
- [ ] 提供迁移失败回滚和旧格式导出方案；密钥继续通过现有凭据机制独立保管。

验收：迁移前后记录与证据引用一致，报告校验通过；并发更新不会丢失数据；中断迁移不会破坏原始文件；查询支持按 Case、任务及状态分页。

## 4. 任务事件推送与增量刷新（优先级 P2，依赖稳定事件接口）

现状：前端仍约每 2.5 秒轮询多组数据并重新渲染。已合并重叠刷新、保留任务树展开状态，但尚无事件推送。

- [ ] 设计带递增事件 ID 的任务事件格式，覆盖创建、状态、预算、证据、完成和失败。
- [ ] 优先评估 SSE；只有需要双向长连接时再考虑 WebSocket。
- [ ] 按当前 Case 订阅，支持断线重连、去重、顺序处理和遗漏事件补取。
- [ ] 前端按受影响的记录增量更新，保留滚动位置、输入草稿及展开状态。
- [ ] 保留轮询降级与首次全量快照，避免推送不可用时页面失效。

验收：状态更新无需等待固定轮询；重连不重复插入记录；切换 Case 不显示上一 Case 的事件；服务重启后能重新取得一致状态。
